# ADR-0006: MCP para integração com sistemas externos

- **Status:** aceito e **implementado** nesta versão (na versão Java ficou só a interface) · **Data:** 2026-10-07

## Contexto
O cenário menciona integrar dados externos via MCP. O agente depende de ERP, orçamento e cadastro de fornecedores.

## Decisão
- Toda leitura externa passa pela porta `ErpGateway` (Protocol, somente leitura), com duas implementações selecionadas por `ERP_SOURCE`:
  - `MockErpGateway` (in-process, default): rápido e usado nos testes unitários e no golden set.
  - **`McpErpGateway`** (cliente MCP, `mcp` 2.x): consome o servidor **`erp-mcp`** (`mcp_server/erp_server.py`), que expõe as ferramentas `get_cost_center_budget`, `get_supplier_profile` e `get_purchase_history` via Streamable HTTP (ou stdio).
- **O agente não muda:** a troca de fonte é só de configuração (`ERP_SOURCE=mcp`, `MCP_ERP_URL`). O teste `test_full_pipeline_over_mcp_erp` roda o pipeline inteiro sobre MCP, e a demo roda o servidor MCP em outro processo (`scripts/run-with-mcp.sh`).
- **Falha de MCP = fonte indisponível:** rede, timeout (5 s) ou erro de protocolo viram `ContextSourceUnavailable`, que vira `EV-SRC-*`, o que bloqueia aprovação automática (`test_mcp_gateway_maps_unreachable_server_to_unavailable_source`).
- **Ferramentas são chamadas pelo código (pré-busca), não pelo LLM** ([ADR-0003](0003-contexto-pre-buscado-vs-tool-calling.md)). O MCP padroniza a integração sem dar ao modelo autonomia para escolher ferramentas.

## Trade-offs: MCP vs. skills/scripts internos
| | MCP | Integração interna |
|---|---|---|
| Reuso por outros agentes e ferramentas | ✅ Padrão aberto; o mesmo `erp-mcp` serve este agente, o Claude Desktop/Code ou outro agente | ❌ Acoplado a este serviço |
| Governança | ✅ Allowlist de tools, autenticação e auditoria centralizadas no servidor | Dispersa |
| Latência | ❌ Hop extra (rede + sessão MCP por chamada) | ✅ In-process |
| Operação | ❌ Mais um componente para versionar, monitorar e escalar | ✅ Simples |
| Segurança | ⚠️ Superfície nova: autenticação do servidor, escopo das tools, e o resultado da tool é **dado não confiável** (validado pelos mesmos parsers tipados) | Menor |
| Testabilidade | ✅ O SDK conecta o cliente a uma instância do servidor in-process (sem rede) | ✅ Mock direto |

**Recomendação:** MCP para sistemas **compartilhados entre agentes** (ERP, cadastro); integração interna para lógica **exclusiva do agente** (motor de regras, validador).

## Limitações desta implementação
- Uma sessão MCP por chamada de ferramenta (3 por decisão): é simples e stateless, porém mais lento. Evolução: sessão por requisição, pool de sessões ou uma ferramenta agregada (`get_purchase_context`).
- O servidor MCP não tem autenticação (roda em `127.0.0.1`). Em produção: OAuth (o SDK suporta `auth_server_provider`/`token_verifier`) e TLS.
